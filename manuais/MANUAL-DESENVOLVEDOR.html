1. Objetivo e arquitetura

Ferramenta HTML5/Canvas offline, sem bundler, com renderização FPS por raycasting. O editor e o jogo são integrados na mesma página, mas mantêm responsabilidades distintas. O formato de mapas é JSON.

2. Estrutura do projeto

index.html            Estrutura HTML, botões e janelas
assets/               Logotipo e ícone WMK
css/style.css         Tema, HUD, layout e responsividade
js/core.js            Tipos de blocos, mapa, Game, regras e colisões
js/layers.js          Camadas, pintura e serialização
js/renderer.js        Raycaster e desenho da vista 2.5D
js/app.js             Interface, eventos, mouse/teclado, editor
js/layouts.js         Janelas, persistência e presets
manuais/              Documentação em português
tests/test-core.js    Testes automatizados
LICENSE               Licença MIT

3. Fluxo de execução

index.html → core.js → layers.js → renderer.js → app.js → layouts.js
                                            └→ WMKRenderer.render(canvas, game)

Mapa editável → WMKLayers.serialize() → arquivo JSON
JSON importado → WMKCore.normalize() → WMKLayers.ensure()
Botão JOGAR FPS → new WMKCore.Game(map) → loop requestAnimationFrame

4. Módulos e responsabilidades

MóduloResponsabilidade e cuidados
core.jsRegras puras, estado do jogador, interações e validação. Evitar dependências de DOM.
layers.jsPintura e armazenamento por camada. Normalizar dados de projetos antigos.
renderer.jsCalcular interseções com paredes, aplicar texturas e sprites. Otimizar antes de aumentar resolução.
app.jsConectar DOM, atalhos, eventos, input e comandos da interface.
layouts.jsIsolado do modelo de mapa: mover/redimensionar painéis, presets e armazenamento local.

5. Formato de dados e persistência

Os mapas usam propriedades como name, width, height, cells, objects e dados de camadas. Confirme o contrato nas funções blank, normalize, serialize e ensure antes de alterar.

O gerenciador de layouts armazena um dicionário nome → posições (x,y,w,h) para tools, center e right. Chaves de navegador: wmk_retro_layouts_v1 e wmk_retro_layout_active_v1. Não se misturam com o arquivo de mapa.

6. Estendendo o programa

  1. Crie um tipo de tile/objeto no catálogo do núcleo em core.js.
  2. Adicione sua representação na paleta do editor (app.js).
  3. Implemente colisão, interação e efeitos no Game.
  4. Renderize o tipo na vista 2D e, se preciso, no renderer.js.
  5. Garanta que o tipo seja serializado corretamente no JSON.
  6. Crie teste de regra isolado em tests/test-core.js.
  7. Atualize os dois manuais e o roadmap.

7. Testes e depuração

O aplicativo roda no navegador; com Node.js opcional, execute:

node tests/test-core.js
node --check js/core.js
node --check js/layers.js
node --check js/renderer.js
node --check js/app.js
node --check js/layouts.js

Os testes cobrem regras do núcleo, não substituem teste visual do navegador. Use F12 → Console para erros de execução, F12 → Network (quando usando servidor HTTP) para recursos e Performance para renderização.

8. Checklist de revisão manual

  1. Abrir index.html sem erros no console.
  2. Ver logo no editor e ícone no modo FPS.
  3. Arrastar os três painéis pela barra de título sem mover conteúdos internos.
  4. Redimensionar cada painel pela alça inferior direita.
  5. Salvar, carregar, renomear e excluir um preset.
  6. Exportar/importar presets JSON, recarregar a página e observar persistência.
  7. Pintar mapa, salvar JSON, abrir o mesmo mapa, jogar e testar colisões/chaves.

9. Cuidados de segurança e licenciamento

Arquivos JSON externos devem ser validados antes de uso. Evite incorporar scripts arbitrários de mapas sem sandbox e permissões explícitas. Limite dimensão de mapas e tamanho de imagens para evitar travamentos e estouro de memória. A MIT rege o código próprio; recursos de terceiros são licenciados separadamente. Não copie código nem texturas comerciais de Easy FPS Editor, Wolfenstein 3D, Mario ou Counter-Strike.

10. Prioridades e melhorias

Editor visual de eventos, sprites de inimigos animados, mais ferramentas de pintura, exportador de jogo separado do editor, biblioteca de mapas, salvamento de projetos com migração de schema, testes E2E com automação de navegador e perfis de qualidade para máquinas modestas.

11. Contribuindo pelo GitHub

  1. Faça fork de WMK-RETRO-STUDIO.
  2. Crie branch descritiva, faça a alteração e teste.
  3. Documente comandos, imagens de teste e limitações.
  4. Abra Pull Request. Preserve créditos do autor e histórico da licença.
